# Flash Sales 平台技术文档

## 项目概述

Flash Sales 平台是一个基于微服务架构的高并发秒杀系统，采用异步编程模型和现代云原生技术栈构建。系统设计目标为支持万级QPS的秒杀场景，保证数据一致性和系统可用性。

## 技术架构

### 1. 后端框架：FastAPI
**技术说明**：
- **版本**: FastAPI 0.135.3 + Python 3.13.9
- **架构优势**：
  - 基于ASGI标准的异步Web框架，支持全链路异步处理
  - 自动生成OpenAPI 3.0文档，支持Swagger UI和ReDoc
  - 内置数据验证（Pydantic），类型安全
  - 依赖注入系统，支持分层架构
- **性能特性**：
  - 使用Starlette作为底层ASGI服务器
  - 支持WebSocket、Server-Sent Events等实时协议
  - 中间件系统支持CORS、HTTPS重定向等

### 2. 数据库层：PostgreSQL + SQLAlchemy Async
**技术说明**：
- **数据库**: PostgreSQL 15，采用异步驱动asyncpg
- **ORM**: SQLAlchemy 2.0+ 异步版本
- **设计特点**：
  - 连接池管理：使用asyncpg连接池，最大连接数100
  - 事务管理：支持嵌套事务和保存点
  - 数据模型：定义在`app/models/`目录，包含用户、产品、订单、秒杀产品等核心实体
- **性能优化**：
  - 索引策略：对高频查询字段（如用户邮箱、产品ID）建立B-tree索引
  - 分区表：订单表按时间分区，支持历史数据归档
  - 读写分离：支持配置主从复制（当前为单节点）

### 3. 缓存与队列：Redis
**技术说明**：
- **版本**: Redis 7.2，支持Streams数据结构
- **使用场景**：
  1. **库存预减**：秒杀开始前将商品库存加载到Redis，通过DECR原子操作保证库存一致性
  2. **分布式锁**：使用Redlock算法实现分布式锁，防止超卖
  3. **限流器**：令牌桶算法实现API限流（`app/utils/limiter.py`）
  4. **会话存储**：JWT黑名单和用户会话缓存
  5. **消息队列**：Redis Streams作为轻量级消息队列，处理订单异步创建
- **配置**：
  - 连接池大小：50
  - 超时设置：连接超时5s，读写超时3s
  - 序列化：Msgpack（高性能二进制序列化）

### 4. 消息队列：Kafka
**技术说明**：
- **版本**: Apache Kafka 3.5
- **架构角色**：
  - **生产者**：`app/services/kafka_producer.py`，异步发送订单创建事件
  - **消费者**：`app/services/seckill_service.py`中的`consume_orders()`方法
  - **主题**：
    - `seckill-orders`: 秒杀订单创建事件
    - `order-status-updates`: 订单状态更新事件
- **保证机制**：
  - 至少一次投递（at-least-once delivery）
  - 分区键：用户ID，保证同一用户订单顺序处理
  - 副本因子：3（生产环境配置）

### 5. 任务调度：APScheduler
**技术说明**：
- **集成位置**: `app/tasks/scheduler.py`
- **调度策略**：
  - 后台线程池执行器，支持并发任务
  - 支持Cron表达式、间隔触发、日期触发
- **定时任务**：
  1. **库存同步**：每小时同步数据库库存到Redis
  2. **订单超时处理**：每5分钟检查未支付订单
  3. **数据统计**：每天凌晨生成销售报表
  4. **日志清理**：每周清理90天前的操作日志

### 6. 认证授权：JWT + OAuth2
**技术说明**：
- **认证流程**：
  1. 用户登录获取access_token和refresh_token
  2. access_token有效期30分钟（可配置）
  3. refresh_token有效期7天，用于令牌刷新
- **安全特性**：
  - 使用HS256算法签名，密钥通过环境变量配置
  - 令牌黑名单：撤销的令牌存入Redis，有效期同原令牌
  - 密码哈希：bcrypt算法，工作因子12
- **权限控制**：
  - 基于角色的访问控制（RBAC）
  - 权限粒度：API端点级别
  - 管理员权限：通过`app/admin/`目录下的路由实现

### 7. 监控与可观测性
**技术说明**：
- **Prometheus指标**：
  - HTTP请求计数、延迟、错误率
  - 数据库连接池状态
  - Redis命中率、内存使用
  - 自定义业务指标（秒杀成功率、订单创建速率）
- **日志系统**：
  - 结构化日志（JSON格式）
  - 日志级别：DEBUG、INFO、WARNING、ERROR
  - 日志输出：控制台 + 文件 + ELK集成（可选）
- **分布式追踪**：
  - OpenTelemetry集成（`app/middleware/trace.py`）
  - 跟踪ID传播：通过HTTP头`X-Trace-Id`
  - 采样率：生产环境1%，开发环境100%

### 8. WebSocket实时通知
**技术说明**：
- **实现位置**: `app/websocket/order_notify.py`
- **协议**: WebSocket over TCP
- **使用场景**：
  1. 订单状态实时更新
  2. 秒杀开始通知
  3. 库存变化广播
- **技术特性**：
  - 连接管理：使用`websockets`库，支持心跳检测
  - 广播机制：Redis Pub/Sub实现跨进程消息广播
  - 连接认证：WebSocket握手时验证JWT令牌

### 9. AI集成：提示增强服务
**技术说明**：
- **API端点**: `POST /api/v1/prompt/enhance`
- **实现逻辑**：
  1. **AI增强模式**：如果配置了`OPENAI_API_KEY`，使用GPT-4模型进行智能提示优化
  2. **规则增强模式**：否则使用基于规则的模板增强
- **支持风格**：
  - professional（专业）：添加专业框架和术语
  - creative（创意）：增加比喻和生动描述
  - concise（简洁）：精简语言，突出重点
  - detailed（详细）：扩展细节，提供示例
- **配置**：
  - 默认使用SC-Net API（国产大模型服务）
  - 模型：Qwen3-235B-A22B
  - 超时：10秒，重试2次

### 10. 容器化与部署
**技术说明**：
- **Docker配置**：
  - 多阶段构建，减小镜像体积（~300MB）
  - 基础镜像：python:3.13-slim
  - 分层缓存：依赖层与代码层分离
- **Docker Compose服务**：
  - `api`: FastAPI应用，热重载支持
  - `db`: PostgreSQL数据库，数据卷持久化
  - `redis`: Redis缓存，AOF持久化
  - `adminer`: 数据库Web管理界面（可选）
- **健康检查**：
  - 应用层：`/health`端点
  - 容器层：Docker健康检查命令
  - 就绪探针：检查数据库和Redis连接

### 11. 高并发设计模式
**技术说明**：
1. **库存预减模式**：
   - 秒杀开始前将库存加载到Redis
   - 使用`DECR`原子操作减少库存
   - 库存为0时直接返回售罄，避免数据库压力

2. **队列缓冲模式**：
   - 用户请求进入Redis Streams队列
   - 后台消费者异步创建订单
   - 返回排队中状态，前端轮询结果

3. **限流与熔断**：
   - 令牌桶限流：API级别限流
   - 用户级限流：同一用户每秒最多1次请求
   - 熔断器：失败率超过阈值时暂时拒绝请求

4. **缓存策略**：
   - 热点数据：产品信息、用户信息缓存5分钟
   - 写穿透：先更新数据库，再删除缓存
   - 缓存击穿：使用互斥锁防止大量请求同时查询空数据

### 12. 数据一致性保证
**技术说明**：
1. **最终一致性**：
   - 订单创建：先扣减Redis库存，异步创建数据库订单
   - 使用Kafka保证事件至少投递一次
   - 补偿机制：定时任务检查不一致状态

2. **分布式事务**：
   - Saga模式：长事务拆分为多个本地事务
   - 补偿事务：每个正向操作对应一个补偿操作
   - 状态机：订单状态机保证状态转换合法性

3. **幂等性设计**：
   - 请求ID：客户端生成唯一请求ID
   - 幂等键：基于用户ID+产品ID+时间戳
   - 存储层：数据库唯一约束防止重复创建

### 13. 安全防护
**技术说明**：
1. **输入验证**：
   - Pydantic模型验证所有API输入
   - SQL注入防护：参数化查询
   - XSS防护：输出编码，CSP头

2. **API安全**：
   - 速率限制：防止暴力破解
   - JWT令牌：短期有效，自动刷新
   - CORS配置：严格的白名单策略

3. **数据安全**：
   - 敏感数据加密：密码、令牌等
   - 审计日志：所有操作记录到`operation_logs`表
   - 数据脱敏：日志中的敏感信息掩码处理

## 性能指标

### 基准测试结果
- **单节点QPS**：健康检查端点 ~5,000 QPS
- **秒杀场景**：库存预减 ~10,000 QPS
- **数据库查询**：简单查询 ~2,000 QPS
- **Redis操作**：~50,000 OPS

### 资源消耗
- **内存**：空闲时 ~200MB，高峰时 ~1GB
- **CPU**：平均使用率 5-20%，秒杀时可达 60%
- **网络**：平均带宽 10-50 Mbps

## 扩展性设计

### 水平扩展策略
1. **无状态API层**：可通过负载均衡器横向扩展
2. **数据库分片**：按用户ID哈希分片
3. **缓存集群**：Redis Cluster支持数据分片和高可用
4. **消息分区**：Kafka主题分区，消费者组并行处理

### 垂直扩展策略
1. **连接池优化**：根据负载调整数据库和Redis连接数
2. **线程池调整**：异步任务执行器线程数配置
3. **内存优化**：调整Python GC策略，使用内存池

## 故障恢复

### 容错机制
1. **服务降级**：AI服务不可用时降级到规则引擎
2. **自动重试**：网络故障时指数退避重试
3. **优雅关闭**：收到SIGTERM时完成当前请求再退出

### 灾难恢复
1. **数据库备份**：每日全量备份 + 每小时增量备份
2. **配置管理**：环境变量 + 配置文件版本控制
3. **回滚策略**：Docker镜像标签，快速回滚到稳定版本

## 开发与运维

### 开发环境
- **本地开发**：Docker Compose一键启动
- **热重载**：uvicorn --reload 监控代码变化
- **调试工具**：pdb调试器，FastAPI调试中间件

### 部署流程
1. **CI/CD**：GitHub Actions自动化测试和构建
2. **容器注册**：推送到Docker Hub或私有Registry
3. **滚动更新**：Kubernetes Deployment滚动更新策略
4. **蓝绿部署**：生产环境流量切换策略

## 总结

Flash Sales平台采用了现代化的微服务架构和云原生技术栈，通过异步编程、缓存策略、消息队列和分布式系统设计，实现了高并发、高可用、可扩展的秒杀系统。系统在保证数据一致性的同时，提供了优异的性能表现和良好的开发者体验。
